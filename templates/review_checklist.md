# 代码审查检查清单

> 🔍 供Reviewer Agent和所有Engineer Agent使用。代码合并前必须通过的检查项。

---

## 通用检查项 (所有语言/框架)

### 功能正确性
- [ ] 代码实现了需求/任务描述的全部功能
- [ ] 边界条件有正确处理（空值、极值、异常输入）
- [ ] 错误情况有适当的错误处理和用户提示
- [ ] 没有引入范围蔓延（不相关的修改）

### 代码质量
- [ ] 命名清晰，见名知意
- [ ] 函数/方法长度合理（< 50行）
- [ ] 没有重复代码（DRY原则）
- [ ] 没有过度抽象（KISS原则）
- [ ] 注释解释了"为什么"而非"做什么"
- [ ] 没有注释掉的代码

### 安全性
- [ ] 用户输入有校验和清理
- [ ] SQL查询使用参数化（防注入）
- [ ] 敏感信息不在日志/前端中暴露
- [ ] 认证和授权检查正确
- [ ] 没有硬编码的密钥/Token

### 性能
- [ ] 没有不必要的循环嵌套
- [ ] 数据库查询没有N+1问题
- [ ] 大列表有分页或虚拟滚动
- [ ] 资源有适当的释放/清理

### 测试
- [ ] 核心逻辑有单元测试
- [ ] 边界条件有测试覆盖
- [ ] 新代码未破坏已有测试

### 文档
- [ ] API变更更新了API文档
- [ ] 复杂逻辑有必要的注释
- [ ] README/部署文档有相应更新

---

## 前端专项检查

### React/Vue 组件
- [ ] 组件职责单一，可复用
- [ ] Props/State类型定义完整 (TypeScript)
- [ ] 使用了正确的Hooks依赖数组
- [ ] 没有在render中创建新对象/函数（避免不必要的re-render）
- [ ] 大列表使用了key且key稳定

### 状态管理
- [ ] 状态放在正确的层级（局部 vs 全局）
- [ ] 异步状态有loading/error/data三态处理
- [ ] 没有过时的闭包问题

### UI/UX
- [ ] 响应式设计覆盖目标设备
- [ ] 可访问性达标（键盘导航、屏幕阅读器）
- [ ] 加载状态有skeleton/spinner
- [ ] 空状态有友好提示
- [ ] 错误状态有重试/恢复机制

### 性能
- [ ] 大图片有懒加载
- [ ] 代码分割合理
- [ ] 没有过大的bundle
- [ ] 列表 > 100项有虚拟滚动

---

## 后端专项检查

### API
- [ ] 输入参数校验完整
- [ ] 返回统一的响应格式
- [ ] HTTP状态码使用正确
- [ ] 错误信息不泄露内部实现
- [ ] API版本化管理

### 数据库
- [ ] 数据库迁移脚本正确
- [ ] 索引覆盖查询条件
- [ ] 事务边界正确
- [ ] 没有在循环中查询数据库

### 安全
- [ ] Token验证在中间件中
- [ ] 文件上传有大小和类型校验
- [ ] CSRF保护在状态变更操作中

---

## DevOps专项检查

### CI/CD
- [ ] 配置文件语法正确
- [ ] 敏感信息使用Secrets
- [ ] 构建缓存合理配置
- [ ] 部署有回滚机制

### 容器
- [ ] 使用非root用户
- [ ] 健康检查端点配置
- [ ] 日志输出到stdout/stderr
- [ ] 镜像大小合理

---

## 审查意见分类

| 级别 | 含义 | 处理要求 |
|------|------|---------|
| 🔴 Blocking | 必须修复才能合并 | 立即修复 |
| 🟡 Important | 应该修复，有充分理由可豁免 | 本PR修复或创建Issue |
| 🔵 Nitpick | 建议性的小改进 | 自行决定 |
| 💬 Question | 不理解，需要讨论 | 作者回复 |
| 👍 Praise | 做得好，值得鼓励 | - |

---

## 审查完成条件
- [ ] 所有 🔴 Blocking 意见已解决
- [ ] CI管道全部通过
- [ ] 测试覆盖率未下降
- [ ] 相关文档已更新
